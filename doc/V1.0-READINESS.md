## Needs a user decision (not blocking, but 1.0 should decide)

1. **Taxonomy distribution — DECIDED (embed) and implemented.** CI embeds the
   pinned index (data-only release `taxonomy-k7-20260901`, sha256-verified)
   into every platform tarball at tag time, keeps the standalone asset via an
   independent job, and a release-completeness check fails red on any missing
   asset. See the "Embed taxonomy index" steps in both workflows.
2. **macOS signing.** The user's stated gate — F2 and F4 rolled in — is met
   (both shipped 2026-09-01, see doc/BACKLOG.md), so the 7 `MACOS_*` secrets
   (reusable from BALL) can be added whenever convenient; every tag build
   still takes the "not configured" branch until then. Runbook:
   `doc/SIGNING-macos-gui.md`.
3. **F5 — DECIDED (folded into F1/F2).** Direct PTM-Shepherd interop is a
   category mismatch (it consumes only Philosopher psm.tsv + spectra); the
   honest deliverable — recon delta columns + a `-delta_out` histogram — rides
   on F2. See doc/BACKLOG-PLAN-2026-09.md §0.3/§1.2.
4. **F10** low-latency single-spectrum tagging (real-time use): build + benchmark, or drop from the roadmap.
5. **F11** glyco oxonium *flag* (not full glyco): cheap, but only worth it if a user exists.
6. **F12** top-N tags per spectrum for chimeric/DIA: `-max_tags` exists; a per-precursor top-N is a design decision.
7. **F14** overlap-friendly long reads for antibody assembly: nearly free given F4+F13, but needs a consumer (Stitch/ALPS) to validate against.

## 1.0 gate — MET, released 2026-09-02

(a) CI green on all platforms (build + windows, commit 3a32482); (b) taxonomy
asset attached AND embedded into every tarball by CI; (c) decision 1 made
(embed); (d) signing **explicitly waived for 1.0** — no MACOS_*/SIGNPATH_*

### Cross-version performance, measured 2026-09-02

Full matrix in the release notes. Headlines vs v0.19.1: default tagging
unchanged and byte-identical; `-fasta` filtering 1.2-2.8x faster (bigger
databases gain most, a small one costs ~10% more memory); `-out_spectra`
memory bounded (5272 -> 748 MB on a 1.9 GB input) at 2.4x the wall time;
13 GB tagging memory 1908 -> 1611 MB.

### One unresolved numerical curiosity

On the 13 GB ddaPASEF file, v0.19.1 produced two different outputs across 7
runs, differing in exactly ONE row's E-value in the 5th significant figure
(5.40765 vs 5.40639, a noise-level tag, no sequence or mass change). 1.0 did
not reproduce it in 15 runs, but the scoring path is unchanged between the two
versions, so this is recorded as "not reproduced, mechanism unidentified" --
not as a fix. Worth re-checking if bit-reproducibility on ddaPASEF data ever
becomes load-bearing.
