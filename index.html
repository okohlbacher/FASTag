FASTag

Read short peptide sequences straight from MS/MS spectra, without a database search, and keep only the spectra that match the proteins you care about.

FASTag is for proteomics researchers with DDA, PRM or pseudo-DDA data who want a quick look at a run before, or instead of, a full search: pull out the spectra of a protein of interest, see which organisms a run contains, or hand tags to de novo and open-modification tools. It runs as a desktop app or as an OpenMS command-line tool on macOS, Windows and Linux, and tags three million spectra in about seven seconds on a 128-thread server.

Download GitHub Documentation

An OpenMS command-line (TOPP) tool with a desktop app — reads mzML, mzPeak and MGF, writes tab-separated tags, and drops into an OpenMS pipeline like any other.

What it does

A sequence tag is a run of three or more amino acids read from the mass differences between consecutive fragment ions of one spectrum — no database search and no enzyme assumption needed. FASTag is a fast, sensitive prefilter: it tells you what is worth looking at before you commit to a database search or de novo sequencing.

  • Narrow a huge search space to the spectra carrying a tag from your protein(s) of interest, with -fasta.
  • Get a sense of what is in a run — which organisms (at genus level), contaminants, a specific protein — without a full database search.
  • Feed tags into a downstream tool: open-modification search, spectral clustering, de novo seeding.

Input: mzML, mzPeak or uncompressed MGF with MS/MS spectra of one precursor each — DDA, PRM, or the pseudo-DDA spectra that DIA tools such as DIAspeXtract or diaTracer derive. Raw DIA files are refused with a message; convert them to pseudo-DDA first. Output: a tab-separated table of ranked tags per spectrum, optionally the matching spectra as mzML or mzPeak.

A few rows of the tag table (selected columns, PXD000001, FASTag 1.14.0). Each row is one tag: the residues read, the mass left unexplained on its N- and C-terminal side, and an E-value (smaller is better):

It is a prefilter, not a final identification method. It is tuned for recall: it would rather report a wrong candidate than miss a right one, so a tag matching a sequence is a reason to look closer, not an identification. Tags carry no FDR; I and L are not distinguished (reported as L); b/y ions are assumed by default (-ion_series auto for ETD/ECD); ion-trap MS2 is supported but not validated.

The algorithm is a reimplementation of DirecTag (Tabb et al., J. Proteome Res. 2008, 7:3838). How to cite FASTag itself: see Citation.

FASTag's own defaults (gaps, deisotoping) rank a valid tag first more often than the DirecTag-matched settings: 93.1% vs 90.9% on PXD000001 (Orbitrap, Mascot truth), 67.3% vs 64.7% on PXD054073 (timsTOF ddaPASEF) and 53.8% vs 48.0% on PXD076528 (Astral DDA; both against Sage at 1% FDR). DirecTag's times and memory are from the same node with the same inputs (2026-11-15); its PXD000001 accuracy is from the 2026-09-07 run (BENCHMARK-DirecTag.md). Every number here, with the scripts, input checksums and per-run rows: speed and accuracy.

On the default path memory is flat in the file size rather than proportional to it, so a run is bounded by threads, not by input (-out_spectra and a few reports keep per-run state). Both tools reach the same accuracy ceiling on PXD000001 — 98.62% of the spectra identified by its Mascot search get a valid tag — and FASTag gets there sooner in the ranking. By default FASTag refuses raw DIA such as PXD028735; tag it through pseudo-DDA spectra instead.

Download

Current release: see the release page (what changed). Every release has the command-line tool and a desktop app that runs it: pick files and options in a form, follow progress, and browse tags, spectra and reports.

Binaries are self-contained — the tool, its libraries and the OpenMS data it needs. macOS builds are signed with a Developer ID certificate, notarized by Apple, and the disk images carry their notarization ticket, so they open with no network connection.

Quick start

Desktop app: open it, choose a spectrum file and an output folder, check the fragment tolerance, and press Run; the tag table opens when the run is done. Command line: the default fragment tolerance is 20 ppm, right for Orbitrap, timsTOF and Astral MS2. On ion-trap MS2 set it to 0.3 Da: a tolerance that is too tight gives almost no tags rather than an error.

Try it on the example run shipped with every release (FASTag/examples/; ion-trap MS2, hence 0.3 Da). The tutorial walks through it with expected output; the desktop app manual opens the same data with File > Open Example Data.

# tags for every MS2 spectrum: 139 MS2 spectra, 5937 tags
FASTag -in examples/Ecoli_MS2_small.mzML -out tags.tsv \
       -fragment_tolerance 0.3 -fragment_tolerance_unit Da

# keep only tags occurring in three E. coli proteins, and the spectra carrying them
FASTag -in examples/Ecoli_MS2_small.mzML -out hits.tsv \
       -fragment_tolerance 0.3 -fragment_tolerance_unit Da \
       -fasta examples/Ecoli_MS2_small.fasta -extension 1 -out_spectra hits.mzML

On your own data:

# tags for every MS2 spectrum in a run
FASTag -in run.mzML -out tags.tsv

# high-resolution data, seed length 3 extended to at most 15 residues
FASTag -in run.mzML -out tags.tsv -tag_length 3 -extension 6

# ion-trap MS2 — set the tolerance to match the analyser
FASTag -in run.mzML -out tags.tsv -fragment_tolerance 0.3 -fragment_tolerance_unit Da

# keep only tags occurring in a protein of interest, and the spectra carrying them;
# tags must reach about 4 residues for one protein (-extension 1), 7-8 for a proteome (-extension 3)
FASTag -in run.mzML -out tags.tsv -fasta protein.fasta -extension 1 -out_spectra hits.mzML

# mzPeak in, mzPeak out — any combination of mzML and mzpeak works
FASTag -in run.mzpeak -out tags.tsv -out_spectra hits.mzpeak

-threads 0 (the default) uses half the logical cores. Isotope collapsing and one gap per tag are on by default. For the fastest possible run, or to match a tool with no equivalent of either, add -no_deisotope -gaps 0.

mzPeak

FASTag reads and writes mzPeak, the open, Parquet-based file format for mass-spectrometry data. On centroided MS2 tagging is unaffected by which you use: reading a run as mzPeak gives the same spectra as reading it as mzML, and a run written to mzPeak and tagged again reproduces the original tag set exactly.

  • The same tags from mzML and from both mzPeak layouts (PXD003531, 27,345 MS2 spectra).
  • Profile MS2 in mzPeak is centroided on read, which recovers tags a raw profile mzML read loses; profile runs can therefore give different tags from the two formats.
  • -out_spectra to mzPeak refuses spectra with per-peak ion mobility (timsTOF frames); write mzML for those.

FASTag reads and writes mzPeak through OpenMS, built into every released binary.
